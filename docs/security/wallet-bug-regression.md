# Wallet Bug-Class Regression Matrix

Loom tracks historical wallet failures as bug classes. The goal is not to copy
another wallet's design, but to make sure recurring account-abstraction and
multisig failure modes have explicit regression evidence.

## Regression Classes

| Bug class | Loom design rule | Evidence today | Audit-freeze gap |
|---|---|---|---|
| Uninitialized implementation or account takeover | Initialization is one-shot; delegated initialization is self-only; the proxy bootstrap initializer is restricted to the proxy-construction context. | `LoomAccountInitializationFormal` including `check_UninitializedDelegatedAccountRejectsProxyInitializer`, `EIP7702IntegrationTest.testExternalCallerCannotInitializeUninitializedDelegatedAccount`, Certora rule `uninitializedAccountRejectsProxyInitializer`, `account-initialization-context` guard mutation. | Add bytecode manifest evidence for implementation initialization state. Dirty storage from a prior delegation target is a client-side check, not a runtime guard. |
| Mutable upgrade/admin takeover | Proxy is immutable and deployment-cost only; migration is explicit and user controlled. | Proxy tests, `check_NoMutableUpgradeSelectorsThroughProxy`, deployment docs. | Add deployed-bytecode selector scan for upgrade/admin/beacon functions. |
| Arbitrary delegatecall or module backdoor | Account exposes no user-controlled arbitrary delegatecall; executor adapters are deliberately unsupported unless explicitly added. | Unsupported execution mode tests, `executeFromExecutor` rejection, module lifecycle tests. | Add conformance tests for every production ERC-7579 adapter. |
| Signature replay | Signed authority must bind nonce, account, chain, config version, validator, and committed call hash. | Direct execution nonce rollback tests, migration hash-binding tests, EIP-712 domain usage. | Add cross-chain fork tests and ERC-1271 replay-negative fixtures. |
| Guardian cancellation replay | A cancellation approval authorizes exactly one pending instance, and the instance is consumed on both cancellation and successful execution. | `RecoveryManager`, migration, and keystore sync bind a nonce in their cancel digests; `VaultHook` binds a per-slot instance counter, covered by `testGuardianCancellationCannotBeReplayedAgainstARescheduledWithdrawal`, `testExecutedWithdrawalApprovalCannotCancelAnIdenticalLaterOne`, `testGuardianCancellationDoesNotCrossAccounts`, and the `vault-cancellation-instance-nonce` guard mutation. | Symbolic vault properties use an always-valid guardian verifier, so digest binding has concrete coverage only; a verifier that checks signatures symbolically would close this. |
| Session nonce-key collision | Distinct session permissions must not share one ERC-4337 nonce key. | Exact-call and granular validators reject permission IDs that collide after 192-bit nonce-key truncation. | Add SDK helpers that derive and display the canonical nonce key before signing. |
| Guardian duplicate or threshold abuse | Guardian approvals must not count duplicate leaves and must rotate roots through delayed recovery/config paths. | Recovery unit tests and symbolic delay/replacement checks. | Add full guardian ceremony fixture tests and encrypted backup checks. |
| Recovery bypass | Recovery must be visible, delayed, cancellable, and complete-set replacing. | `check_RecoveryDelayIsEnforced`, recovery replacement properties, freeze carveout tests. | Add expiry/cancellation symbolic targets and live ceremony rehearsal. |
| Emergency window shorter than the response it protects | A guardian freeze must outlast the recovery it buys time for, and the one action allowed while frozen must not let a compromised validator outlast the guardians. | `FREEZE_DURATION >= RECOVERY_DELAY + MIN_EXTERNAL_DELAY` pinned by `invariantFreezeOutlastsRecoveryDelay`; `testFreezeCoversRecoveryDelayForAlreadyReadyExternalOperation`, `testFrozenRecoveryCancellationRetiresScheduleAndRearmsGuardians`, `testUnfrozenRecoveryCancellationDoesNotAdvanceConfig`, and the `frozen-recovery-cancellation-config-advance` guard mutation. | The publication margin is a censorship judgement, not a proof; an adversary who can censor recovery execution for longer than the margin still wins. |
| Unbounded pending operation | Every delayed operation has an explicit execution window and an instance identity, and consumption advances that identity. | `SCHEDULE_WINDOW` bounds scheduled calls alongside `RECOVERY_WINDOW`, `SYNC_WINDOW`, `MAX_WITHDRAWAL_WINDOW`, and `MAX_MIGRATION_WINDOW`; `ScheduledOperationLifecycleTest` covers the boundary timestamps, expiry permanence, guardian cancellation, cancellation replay, and execution consumption; `scheduled-operation-expiry` and `scheduled-cancellation-instance-nonce` guard mutations. | Stale consumed slots are retained to keep the instance counter, so storage is never reclaimed; an operation invalidated by a configuration change is still never cleaned up. |
| Module removal stranding a dependent module | A module may not be removed while another installed module declares a dependency on it; the escape hatch that must stay available replaces rather than strands. | `ILoomPolicyBoundValidator` makes the dependency declarable, `_uninstallModule` refuses a depended-on hook on every path, and `evictHookWithGuardians` installs the replacement and rebinds dependents before removal. `ValidatorHookDependency.t.sol` covers refusal, atomic swap, the scheduled-uninstall path, initialization coherence, and rebinding outside an eviction. | Dependency declaration is probed with `try/catch`, so a validator that reverts or omits the interface reads as depending on nothing; that keeps a misbehaving module from vetoing hook removal but means the guard only protects modules that declare honestly. |
| Composite lifecycle bypass | Freeze, migration, scheduled operations, and recovery are overlapping state dimensions; one pending state must not weaken another. | Composite freeze + pending recovery + pending migration regression; lifecycle docs model the state as orthogonal overlays. | Add model-based state-machine campaigns for every overlapping pending-state pair. |
| Spend-limit bypass through calldata shape | A call must be metered on every asset it moves; one shared classifier decides the shape for all enforcement layers. | `MixedValueSpendPolicyTest` covers the direct, batch, scheduled, malformed-calldata, and `isLowRisk`/`validateDirectExecution` paths; `VaultHook.t.sol` covers the vault reclassification; `policy-hook-mixed-value-spend` guard mutation. | Add a rehearsal against real payable token-like targets on a fork. |
| Partial batch state after revert | Atomic execution must leave no partial spending effects. | `check_BatchExecutionAtomicity`, direct batch rollback, migration atomicity tests. | Add ERC-20/non-standard-token rehearsal. |
| Factory or registry authority creep | Factory/registry may deploy or count accounts, but cannot execute, upgrade, freeze, recover, or veto them. | Proxy/factory/registry tests and architecture docs. | Add Certora/Kontrol rules for factory and registry non-authority. |
| EIP-7702 persistent delegation phishing | Delegated setup must be template-bound, visible, and revocable by migration/recovery paths. | Delegated initializer self-only property and 7702 docs. | Client-side clear-signing/template verification and testnet phishing rehearsals. |
| Paymaster overspend or censorship | Paymasters remain optional and policy-limited; core account does not depend on a company paymaster. | Paymaster policy docs and SDK boundaries. | Live sponsored/native fallback evidence across independent bundlers. |

## Review Rule

Adding an account authority feature requires updating this matrix when it
touches initialization, upgrades, modules, signatures, recovery, batching,
factory/registry behavior, delegation, or paymaster policy.
